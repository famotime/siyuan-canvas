# 插件开发入门与工程实践

- 适用版本：SiYuan `v3.8.3`
- 官方仓库同步到：`siyuan-note/siyuan@master` + Release `v3.8.3`（2026-09-13）
- 官方依赖库：`siyuan@1.2.7` / `siyuan-petal@1.2.8-preview`
- 最后核对：2026-09-13
- 稳定性：stable
- 权威来源：
  - <https://github.com/siyuan-note/plugin-sample>
  - <https://github.com/siyuan-note/siyuan>
  - <https://github.com/siyuan-note/petal>

## 1. 目标与快速开工

### 1.1 目标

10~20 分钟内完成“能跑、能调试、具备最新 v3.8.3 交互与生命周期规范”的思源插件。

### 1.2 快速步骤

1. 使用本项目模板初始化仓库（仓库名 = 插件名，默认分支 `main`）。
2. 安装依赖并启动开发热构建（`pnpm i` + `pnpm dev`）。
3. 在 `src/index.ts` 中继承 `Plugin` 并覆盖生命周期（`onload`、`onLayoutReady`、`onDataChanged`、`onunload`、`uninstall`）。
4. 在 `src/kernel.ts` 中声明内核插件（支持本地存储、RPC、Goja 运行时能力与 Agent Capability 注册）。
5. 用插件 API 扩展界面（顶栏、面包屑、动态工具栏、自定义块、Dock、命令面板、设置页），用内核 API 操作数据。
6. 构建 `package.zip` 并发布 GitHub Release 提交集市。

## 2. 开发前置环境

- 语言：TypeScript（强类型约束，强烈推荐）或 JavaScript
- 包管理器：Node.js (>=18) + pnpm (>=8)
- 编辑器推荐：VS Code
- 建议：在独立的测试工作空间中开启插件调试，避免影响日常笔记数据。

## 3. 双端协同架构（前端 + 内核）

思源 v3.8.3 插件体系支持“双端运行”机制：

1. **前端插件 (`src/index.ts`)**：
   - 运行在渲染进程（Electron 窗口或浏览器环境）。
   - 负责 UI 交互、DOM 渲染、事件总线监听、富文本编辑器控制与快捷键绑定。
2. **内核插件 (`src/kernel.ts`)**：
   - 运行在 Go 内核内嵌的 Goja ECMAScript 引擎中。
   - 独立于前端生命周期，随内核启动，支持跨设备同步处理、本地文件持久化 (`IStorage`)、插件间 RPC 调用 (`IRpc`) 以及 AI 智能体能力注册 (`IAgent.registerCapability`)。

## 5. 最小前端插件骨架

```ts
import { Plugin, ICommandContext } from "siyuan";

export default class MyPlugin extends Plugin {
  async onload() {
    // 1. 添加顶栏按钮
    this.addTopBar({
      icon: "iconInfo",
      title: "我的插件",
      callback: () => {
        console.log("顶栏按钮被点击");
      },
    });

    // 2. 动态注册编辑器工具栏按钮 (v3.8.3 新增)
    this.addToolbarItem({
      name: "my-plugin-tool",
      icon: "iconSparkles",
      title: "快速工具",
      click: (protyle) => {
        console.log("工具栏触发，当前 protyle:", protyle);
      },
    });

    // 3. 注册面包屑按钮 (v3.8.3 新增)
    this.addBreadcrumbButton({
      id: "my-breadcrumb-btn",
      icon: "iconFile",
      title: "文档操作",
      callback: (event, protyle) => {
        console.log("面包屑按钮触发", event, protyle);
      },
    });

    // 4. 注册命令 (支持统一 ICommandContext 上下文)
    this.addCommand({
      langKey: "myCommand",
      hotkey: "⌥⌘P",
      execute: (context: ICommandContext) => {
        console.log("命令触发，激活编辑器:", context.protyle);
      },
    });
  }

  onLayoutReady() {
    console.log("界面布局就绪");
  }

  onDataChanged(reason?: "sync" | "overwrite") {
    console.log("插件数据发生变更，来源:", reason);
  }

  onunload() {
    console.log("插件卸载/禁用，释放资源");
  }

  uninstall() {
    console.log("插件被彻底移除，清理残留数据");
  }
}
```

## 6. 自定义块渲染 (`customBlockRenders`)

v3.8.3 原生支持插件扩展自定义块渲染器（`NodeCustomBlock`）：

```ts
this.customBlockRenders = {
  "my-card": {
    render: (options: {
      element: HTMLElement;
      content: string;
      setContent: (content: string) => boolean;
    }) => {
      // options.element 为渲染宿主容器
      options.element.innerHTML = `<div class="my-card">内容: ${options.content}</div>`;

      // 可返回清理回调函数，在块销毁时执行
      return () => {
        console.log("自定义块清理");
      };
    },
  },
};
```

## 7. 生命周期关键契约

思源 v3.8.3 对生命周期引入了**严格的串行机制与 5 秒拆除预算**：

- **严格串行执行**：`onload` -> `onLayoutReady` -> `onDataChanged` -> `onunload` -> `uninstall` 严格按序串行，且等待 Promise 完成。
- **5 秒共享拆除预算**：从收到首次禁用、重载或卸载请求开始，思源启动一份 5 秒全局倒计时。等待先前正在执行的 `onload`/`onDataChanged` 以及后续的 `onunload`/`uninstall` 共享这 5 秒。
- **超时保护**：超时后思源不再阻塞等待，但会尽力调用每个拆除钩子一次，随后强制释放宿主资源。因此，钩子中**严禁编写阻塞式的同步死循环或耗时超长的未超时 Promise**。

## 8. 高频 API 与接口导航

### 8.1 插件 API (UI 与交互)
- 界面组件：`addTopBar`, `addStatusBar`, `addDock`, `addToolbarItem`, `addBreadcrumbButton`, `openTab`
- 消息反馈：`showMessage`, `hideMessage`, `confirm`, `openSetting`
- 密钥变量：`getSecret(name)`, `getVariable(name)`
- 数据存储：`loadData`, `saveData`, `removeData`
- 智能体扩展：`addAgentCapability`

### 8.2 内核 API (数据持久化)
- 块与文档操作：`/api/block/*`, `/api/filetree/*`
- 属性读写：`/api/attr/*`
- 结构化查询：`/api/query/sql`
- 属性视图（AV/数据库）：`/api/av/*`
- 条件与搜索组：`/api/storage/setCriterion`, `/api/storage/getCriterion`

## 9. 构建与发布流水线

1. **类型检查**：`pnpm run typecheck`
2. **代码风格检查**：`npx eslint src/`
3. **生产打包**：`pnpm run build`（将自动生成 `dist/` 产物及根目录 `package.zip`）
4. **发布 Release**：在 GitHub 上创建对应 `version` 的 Tag 和 Release，并上传 `package.zip`。
5. **集市登记**：首次发布向 `siyuan-note/bazaar` 提交 PR 将插件元信息登记到 `plugins.json`。
